## 为什么之前日志正常却一直黑屏

本次实测的关键输出如下，来自终端，非预期值示例：

```text
ADDR,3C,ack=0,raw=1
ADDR,3D,ack=1,raw=0
OLED,ACK=1,ADDR=3D
NEGATIVE,ADDR=2A,ACK=0,EXPECTED
```

`raw`是ACK时刻SDA引脚的原始电平。I2C应答是低电平：raw=0才应解释为ack=1。当前屏幕在7位地址0x3D应答，0x3C和无器件地址0x2A不应答。

旧诊断在无器件地址0x2A也报告ACK成功。进一步逐位读回时，发出的地址与读回一致，但ACK原始电平为高，旧程序仍报告成功。因此先前`screen_write=1,bus_error=0`的结论需要撤回：它不能证明屏幕收到了命令。程序误接受0x3C，就不会继续探测0x3D，后面的文字自然发给了错误地址。

本次把ACK改为**同一次物理采样、保存0/1原始位、显式反相**，再重新探测地址。之后0x3D真实应答、0x2A正确拒绝，屏幕开始出图。

反汇编还发现旧比较表达式使用`SBFX+ADD`，新ACK路径为`UBFX/STRB/LDRB/EOR`。目前能确认的是旧ACK判定在本机仿真中不可信、改写后正常；尚未用独立指令实验确认究竟是处理器模型、指令执行还是其他仿真因素。不能直接宣布“Proteus的SBFX有缺陷”。V05的CPU_BOOL行也不能当作该指令缺陷已验证的证据。

V02还有一个容易误解的地方：发现0x2A意外应答后，它会重新初始化，**不会继续进入全亮测试**。所以此前反复INIT并不能说明A5全亮命令已经执行但无效果。

## 电源和接线这次改了什么

本轮通过的V05保持原工程电源配置：F103的VDD/VDDA为3.3V、VSS/VSSA接地；OLED片段和两只上拉电阻所在默认POWER电网为3.3V，超声模块VCC仍为5V。**没有依靠改成5V来点亮OLED。** 已准备的5V对照副本没有运行，不能把它当成通过方案。

| F103 | 屏幕片段接口 | 用途 |
|---|---|---|
| PB5，41脚 | IO4 → RES | 低电平复位 |
| PB6，42脚 | AD5 → D0 | SCL时钟 |
| PB7，43脚 | AD4 → D1，片段内部兼接D2 | SDA数据 |
| PA9，30脚 | Virtual Terminal RXD | 9600、8N1诊断输出 |
| PB0，18脚 | R1 330Ω → D1 → GND | 阶段指示 |

SCL和SDA各用4.7kΩ作为**信号到3.3V的分支上拉**。信号线直接连到屏幕，不把电阻串进信号。没有改屏幕的模式选择、内部总线和辅助引脚。

UG-2864HSWEG01是裸屏型号，片段省略了实物供电外围。这套仿真接法不等于裸屏实物供电设计；后续实物优先使用带驱动外围的成品OLED模块。

## 正常时会看到什么

V05重复四个阶段：全亮 → 关屏 → 棋盘格 → 文字。每阶段保持约1秒**仿真时间**，写帧另计，因此暂时黑屏可能只是OFF阶段。真实等待时间受仿真速度影响。

完整文字画面为本轮已保存的直接证据；终端还实际出现INIT、ALL_ON、OFF、CHECKER、TEXT各阶段`write_ack=1,bus_error=0`。没有逐阶段各留一张全亮/关屏截图，不能把日志当成每一阶段独立视觉验收。

V04运行时详细GPIO日志较多，窗口出现无响应。已仅关闭该测试副本，保留用户原工程。V05将TRACE属性降到0，并跳过逐位/方向切换审计；本轮输出约7条仿真消息，推进到11.945秒并可正常暂停。这是短时运行证据，不代表长时间稳定性已验证。
