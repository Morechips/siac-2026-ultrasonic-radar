# 仿真内部异常排查

日期：2026年10月14日。

用户日志截图显示Internal Exception: access violation in module MSVCR90.DLL [00023A3E]。这是电脑端模块访问冲突报告，不能单凭这条信息认定STM32的PC跑到无效地址。固件与模型的交互可能触发仿真器问题，原因尚未确定；DLL名称也不能证明该DLL本身损坏。

上一行Logging stopped只表示配置的诊断记录时段结束，不能据相邻日志推断它导致异常。[微软访问冲突说明](https://learn.microsoft.com/en-us/shows/inside/c0000005)解释了非法内存访问的含义。

## 现有证据

- GPIO直接读取诊断已运行，样本持续增加，status=1，echo_us=0，distance_mm=NA，tim2_sr为0或1；PA0未观察到回波，TIM2也未报告捕获事件。回波问题仍未解决。
- 最近自动备份确认Program File为sonar_echo_diag.hex，距离设为50cm。
- 电源轨文件中VDD5V绑定5V、VDD3.3/VDD/VDDA绑定3V3、VSS/VSSA绑定GND；这是配置事实，仍不代替模块引脚实际电压与导通检查。
- 原工程TRACE_GPIO与TRACE_INIT均为3，开启详细诊断记录。尚无证据证明详细日志是异常原因。

## 准备的对照工程

```text
D:\仿真创新大赛\F103入门\stm32f103_sonar_lowtrace.pdsprj
```

工程来源是F103入门中的最近Last Loaded自动备份。仅将ROOT.CDB与ROOT.DSN中的TRACE_GPIO、TRACE_INIT由3降为2；接线、程序选择、电源轨及模型距离保留。相对固件路径仍可在同目录解析。

ZIP完整性与条目一致性已检查通过，两处数据长度均未变化；尚未在Proteus加载或运行确认。自动备份另存于sonar_edu/evidence/故障前自动备份_2026-10-14.pdsbak。当前窗口若有备份之后的新改动，需要用户先正常保存，不能假设这个副本包含所有未保存编辑。

## 用户操作

1. 停止当前仿真，保存当前工程。
2. 关闭并重新打开Proteus，再打开对照工程。
3. 运行约5秒仿真时间，记录是否再出现红色Internal Exception。
4. 若无访问冲突但仍status=1，下一步检查模块实际VCC电压、TR及ECHO波形。
5. 若仍发生相同访问冲突，保留完整日志，再用主控与终端的精简工程区分超声模型、捕获外设和仿真器交互。不要直接更换DLL或把重装软件作为当前结论。
