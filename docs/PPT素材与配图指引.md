## 二、逐页配图方案

### 第 1 页｜封面

- **主图**：网页雷达全景截图（右侧半透明叠加，或整页作背景压暗）
- **标题**：基于 Cortex-M3 的超声旋转扫描雷达实验系统
- **副标题**：Proteus 8.9 仿真 · LM3S317 · 2026 仿真创新大赛（本科组）
- **可截**：网页 `让距离，变得可见` 那句标语很有画面感，可保留在截图里

### 第 2 页｜做什么（应用与痛点）

- **配图**：无图也可以，或用一张"雷达扫描示意"
- **建议放一张小图**：网页上的扇形雷达（圆形扫描区 + 一个绿点）
- **要点文字**（三条以内）：
  - 低速/停车场景下，前方近距障碍难以判断方位
  - 单点测距只有距离，没有方向
  - 让探头转起来，就能同时给出**方向 + 距离**

### 第 3 页｜系统框图（**必须自己画**）

```
  超声模块 SRF04 ──(TR/ECHO: PA2/PA3)──┐
                                        │
  舵机 ──(PWM: PB0)────────────────── [ LM3S317 ] ──(UART: PA1)── [ COMPIM ] ── [ 网页雷达 ]
                                        │            Cortex-M3
  按键 ×3 ──(PB1/PB5/PB4)──────────────┤
                                        │
  I2C EEPROM 24C02C ──(SCL/SDA: PB2/PB3)┘
```

- **风格建议**：MCU 放中间，左边输入（超声、按键），上边控制（舵机），右边输出（串口→网页），下边存储（EEPROM）
- **必须标网络名与引脚号**，体现硬件设计的具体性

### 第 4 页｜硬件选型（**表格 + 原理图小图**）

- **配图**：原理图全景截图（缩到页面右下角，或半幅）
- **表格（三行即可）**：

| 项目 | 候选 | 结论 | 理由 |
|---|---|---|---|
| 主控 | STM32F103 / LM3S317 | **LM3S317** | 本机 Proteus 模型外设行为稳定；F103 在超声回波路径上无法复现 |
| 显示 | OLED / 网页 | **网页** | OLED 模型间歇 NACK 导致整机锁死；改由网页承担可视化 |
| 存储 | 主控 Flash / I2C EEPROM | **24C02C** | 独立器件、页写可靠，同时覆盖 I2C 协议要求 |

> 这一页是加分页：体现"选型有判断，不是堆器件"。

### 第 5 页｜测距原理与软件调度

- **左图（自己画）**：测距时序

```
TRIG  ─┐        ┌────────────────────────────
       └────────┘ 20µs
ECHO  ──────────┐                          ┌─────
                └──────────────────────────┘
                └────── 脉宽 t ────────────┘

距离 = 声速 × t ÷ 2 = t(µs) ÷ 58  (cm)
```

- **右图（自己画）**：时间轴

```
20ms 舵机帧 ─┬─┬─┬─┬─ (每步 N 帧，3° 一步)
             │
             └─ 最后 1 帧：触发 → 测宽 → 上报（限 80ms 一次）
```

- **可截**：终端里 `INFO,SPEED=1/10,STEP_MS=40,SWEEP_MS=2440` 一行作佐证

### 第 6 页｜实测数据（**配表格，最重要的一页**）

| 档位 | 每步 | 理论单程（61 点） | 实测/说明 |
|---|---|---|---|
| 1 | 40 ms | 2.44 s | 最快，步进最密 |
| 4 | 100 ms | 6.10 s | 终端实测 `SWEEP_MS=6100` |
| 10 | 400 ms | 24.4 s | 最慢，适合观察单步 |

| 验证项 | 结果 |
|---|---|
| 测距跟随 | 模块距离 71 → 112 → 123 → 140 cm，串口读数随之变化（710 / 1120 / 1230 / 1400 mm） |
| 存储回放 | 按键触发后输出 31 条 `LOG,...`，角度 3° 递增 |
| 按键 | 停止 / 调速 / 回放 三键全部实测有效 |
| 串口链路 | 5 秒收到 132 行合法 `SCAN` 帧 |

- **配图**：终端 `SCAN,...` 连续输出截图（一张，证明数据在跑）

### 第 7 页｜问题与解决（**技术难度最真实的体现**）

| 现象 | 根因 | 修正 |
|---|---|---|
| 触发正常但始终无回波 | 该 Proteus 超声模型接 **5V 不响应**，必须 3.3V | 模块 VCC 改接 3.3V |
| COMPIM 占住端口但收不到数据 | 引脚按 MCU 侧命名，且默认开硬件流控 | MCU TX 接 **TXD(3)**，关 `HARDFLOW` |
| 按键读不回、I2C 无时钟 | **GPIO 掩码访问误用**：读要移位、写要写掩码值 | `(reg>>pin)&1`；写 `0x04` 而非 `1` |
| EEPROM 应答但读回全 00 | SDA 缺上拉 | SDA 加 10k 到 3.3V |

- **配图**：可选放一张"18 种触发组合全部无响应"的终端截图，很有说服力

### 第 8 页｜边界与展望（**必须如实**）

- **已做**：旋转扫描、测距、存储回放、三键交互、网页可视化、十档调速
- **边界**：
  - 仿真中超声距离由模型设定值给出，**不随角度变化**，验证的是采集—处理—传输—显示链路，不是空间建图
  - 仿真模块供 3.3V；实物 HC-SR04 需 5V，且 ECHO 需电平适配
  - 31 条记录为演示容量，非长时记录
- **展望**：电位器无级调速、实物验证、多传感器融合

- **终端字号调大**（Proteus 终端右键可设字体），保证投屏可读

## 四、可以现场演示的功能（录制视频用）

按演示效果从强到弱排序：

| 顺序 | 操作 | 应看到 |
|---|---|---|
| 1 | 运行仿真 | 终端出现 `BOOT` + `INFO,EEPROM_SELFTEST_OK` + 连续 `SCAN` |
| 2 | 打开网页并连接 COM33 | 雷达出图、距离显示、扫描线转动 |
| 3 | 点模块右侧上下箭头改距离（如 140 → 50） | **串口读数与网页距离同步变化**（最有力的证据） |
| 4 | 按住按键2 | `INFO,SPEED=` 连续变化，扫描明显变快/变慢 |
| 5 | 按按键1 | `INFO,STOP`，扫描停止；再按 `INFO,RUN` 恢复 |
| 6 | 按按键3 | `INFO,REPLAY_START` + 31 行 `LOG`（回放存储记录） |
| 7 | 停止扫描后再按按键3 | 仍能回放 → **证明数据来自 EEPROM 而非实时转发** |

## 五、版式与风格建议

- **比例**：16:9
- **配色**：白/浅灰底 + 一个主色（建议青绿 `#159577`，与网页界面一致）+ 深灰文字
- **字号**：正文 ≥ 24pt，标题 ≥ 32pt，表格 ≥ 18pt
- **每页元素**：1 个标题 + 1 张图 + 2~3 行字，不要大段文字
- **页数**：8 页正文 + 1 页附录（截图清单）足够，讲 6~8 分钟
- **图表优先**：能用表就不用段落，能用图就不用表

## 六、不要写的内容

1. 不要写"实现 SLAM / 建图 / 自主导航 / 避障控制"——本作品没有底盘运动控制
2. 不要写"低成本"却不给 BOM 数字——要么给数字，要么不写
3. 不要把"仿真结果"表述为"实物实测"
4. 不要放没有终端/网页证据的功能
