# 终端空白与启动修正

日期：2026年10月13日。修正版固件：SONAR_V01_1。

用户反馈串口终端持续空白。截图中的PA9已经接到终端RXD；此前源码窗口显示的地址0x08000522与旧固件C运行库堆栈初始化位置吻合。

## 已查到的固件问题

旧startup.s跳转到__main但未提供嵌入式堆栈初始化接口。链接器引入默认sys_stackheap.o，反汇编显示0x08000516有BKPT 0xAB，调用调试器服务SYS_HEAPINFO。这是进入主程序之前的调试器依赖，可能阻止串口代码正常执行。尚未通过新固件的实际运行确认它是本次空白的唯一原因。

启动文件现在显式提供堆栈边界，保留__main的数据复制和清零，退出接口改为本地循环。构建脚本新增反汇编检查，拒绝含BKPT 0xAB的镜像。旧HEX、AXF与map保存在firmware/build/archive_v01。

## 现在如何操作

1. 点击停止仿真。
2. 双击U1，在Program File重新选择修正版：

```text
D:\仿真创新大赛\sonar_edu\firmware\build\sonar_v01_1.hex
```

3. 确认终端为9600、8位、None、1停止位、Normal，PA9接RXD；接线本轮不需要调整。
4. 关闭CM3源码和变量调试窗口，点击运行；观察底部仿真时间持续增加。
5. 预期首先收到：

```text
BOOT,SONAR_V01_1,HSI=8000000,BAUD=9600
```

随后应出现S开头的测量行。50cm输入预期status=0、echo_us约2900、distance_mm约500。

若仍为空白，记录新固件属性、仿真时间及暂停后PC地址，再做仅串口发送的最小验证。不要把修复后编译成功记为仿真通过。

## 修正后的检查结果

- ARMCC5无警告编译和链接成功。
- HEX校验、Flash范围与启动向量检查通过；镜像1372字节，SP为0x20002800。
- 反汇编和map确认默认SYS_HEAPINFO实现已移除，没有BKPT 0xAB。
- 新固件实际串口与测距运行待用户验证。
