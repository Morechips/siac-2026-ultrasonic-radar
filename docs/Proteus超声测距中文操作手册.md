# Proteus超声测距中文操作手册

适用环境：本机Proteus 8.9中文界面、STM32F103C6、HCSR04模型。固件版本：SONAR_V01。日期：2026年10月13日。

本手册帮助你把现有LED工程变成第一阶段超声测距验证工程。按顺序完成保存、供电、串口、固件加载和四项测试，即可确认主控是否真正测到了回波。当前固件已编译并完成静态复核，50cm、100cm、300cm和无回波测试尚未运行确认；文中的数值均为验收预期。

## 1 本次先做到什么

这一轮只测试F103、超声模型和串口终端。舵机、屏幕与扫描算法在这项通过后逐个加入。

正常测量过程是：PA1发出触发脉冲，超声模型在PA0上返回回波，F103测量回波高电平持续时间，换算成距离，再从PA9发送到Virtual Terminal。

50cm设置下，主要检查三项：终端出现启动信息；样本编号持续增加；回波约2900微秒，距离约500毫米。LED可用于观察程序循环，但亮灯和“没有报错”都不能单独证明测距成功。

## 4 核对当前电路

下图是你提供的当前接线截图。它用于定位元件和导线；隐藏电源分配与程序文件路径还需要到各自窗口检查。

你的电路中有U1主控、U2超声模块、PB0上的LED与330Ω电阻、NRST的10kΩ上拉、两种供电端子，以及共同地。D2是此前的电源演示LED，本次可以保留。

按引脚名称核对，不能仅凭图上的上下顺序。你把HCSR04旋转了方向，文字也跟着旋转，应认准VCC、ECHO、TR、GND。

| 元件引脚 | 应连接的位置 |
|---|---|
| U2的TR或TRIG | U1的PA1，芯片11脚 |
| U2的ECHO | U1的PA0，芯片10脚 |
| U2的VCC | 5V电源网络 |
| U2的GND | 共同GND |
| U1的VBAT | 3.3V网络 |
| U1的NRST | 经10kΩ上拉到3.3V |
| U1的BOOT0 | GND |
| U1的PA9 | 后面新增终端的RXD，芯片30脚 |

画线时从引脚端点开始，连到另一端点。线条交叉不一定相连；连接点和实际网络才是依据。需要转弯时点击空白处定拐点，结束后按Esc退出画线状态。

## 5 分开5V与3.3V

两个电源箭头可以使用相同符号，但必须属于不同名称的网络，并设置不同电压。当前截图中的名称是`VDD5V`和`VDD3.3`，本手册沿用这两个名称。

### 5.1 电源分别供给谁

| 网络或电源轨 | 电压 | 本轮用途 |
|---|---:|---|
| VDD3.3 | 3.3V | F103主电源、模拟电源、VBAT、NRST上拉 |
| VDD5V | 5V | HCSR04的VCC |
| GND | 0V | 两部分共同地 |

`VDD5V`和`VDD3.3`是你自定义的网络名称。自定义名称写成`VDD5V`不代表已经完成电压设置；要在电源轨配置中确认。

### 5.2 F103为什么看不到主电源脚

这个F103符号隐藏了VDD、VDDA、VSS、VSSA。图上可见的VBAT只供备份域，不能代替隐藏的主电源。

- VDD、VDDA分配给3.3V电源轨。
- VSS、VSSA分配给GND。
- 可见VBAT在本次无电池配置下接3.3V。

### 5.3 在电源轨窗口操作

1. 停止仿真，打开顶部“设计 → 配置电源线”或“配置电源轨”。中文译名可能略有不同。
2. 本次需要自定义分配，取消勾选底部“使用默认电源连接设置”，避免默认连接覆盖手动设置。
3. 从“名称”下拉框选择`VDD3.3`，确认“电压”为`3.3`。若没有该名称，点击“新建”，输入`VDD3.3`，再设置电压。
4. 查看右侧“网络连接到……”列表：隐藏的VDD、VDDA应在这个3.3V电源轨中。
5. 若VDD或VDDA绑定在其他电源轨，先切换到原电源轨，选中该网络，点击“移除”；再切换到`VDD3.3`，从左侧“未连接电网”选中它，点击“添加”。
6. 选择`VDD5V`，确认电压为`5`。图上的该电源端子直接连到U2 VCC。本轮不要把F103的VDD或VDDA分配到此轨。
7. 选择GND，确认VSS、VSSA属于这个0V轨；未连接时按同样方式添加。
8. 点击“确定”，再打开一次检查设置是否保留，然后Ctrl+S保存工程。

如果某项电压框不能编辑，先看电源端子是否已经用`+5V`等名称显式定义电压；这类供电的电压由端子名称决定。不要只看灰色框就判断失败。遇到无法移动的网络，还要检查原理图上是否用导线把两种电源短接了：已经画线相连的电源网络不能仅靠修改名称分开。

3.3V和5V之间不画连接线；两部分的GND相连。电源轨列表里出现某网络，是网络分配信息，不是实体引脚清单。

## 7 添加Virtual Terminal

Virtual Terminal是本轮的数据显示窗口。它接收主控发来的串口文字，不需要外部串口驱动，也不需要COMPIM或虚拟COM口对。

### 7.1 放置仪器

1. 点击左侧“虚拟仪器模式”。不同中文界面可能只有一个仪表或波形样式图标，可把鼠标停在图标上查看提示。
2. 在仪器列表中选择`VIRTUAL TERMINAL`或`Virtual Terminal`。
3. 在原理图空白处点击放置，然后按Esc退出放置状态。
4. 将F103的PA9连接到终端的RXD。

本轮方向是“主控TX → 终端RXD”。F103发数据，终端接收数据。终端TXD、RTS、CTS暂不连接；本版固件只发送，不接收控制命令。

### 7.2 设置串口参数

停止仿真后双击终端主体，检查属性：

| 属性 | 本轮值 |
|---|---|
| Baud Rate | 9600 |
| Data Bits | 8 |
| Parity | None |
| Stop Bits | 1 |
| RX/TX Polarity | Normal |
| XON/XOFF | 关闭或0 |

本机默认值已经匹配这些参数；如果你没有改过，通常不用额外修改。`8N1`就是8位数据、无校验、1位停止位。MCU的TTL串口直接连接终端时保持Normal，不要设置Inverted。

### 7.3 先验证串口再判断超声

点击左下角三角形运行按钮。终端应自动弹出；如果没弹出，在运行期间的“调试”菜单查找该Virtual Terminal窗口并显示。不要把未打开终端误判为没有串口输出。

启动约0.2秒仿真时间后，预期出现：

```text
BOOT,SONAR_V01,HSI=8000000,BAUD=9600
```

出现这行，说明已观察到程序启动和串口发送。随后每个测量循环都会输出一行；即使没有回波，也应继续输出错误状态。若仿真运行速度低于实时，现实中等待时间会更长，应同时观察仿真时间和样本编号。

## 8 设置超声距离

本机HCSR04模型用内部距离设定值生成ECHO，默认`SETPOINT=50`，单位cm；校准参数默认`CAL=58`，单位微秒每厘米。模型范围为3—500cm。

先使用默认50cm。双击超声主体查看属性；距离可能显示为Distance、Setpoint或类似译名。若属性窗口未显示而模块上有距离读数和调整控件，可在运行时用对应控件调整，再以读数确认。不要修改CAL来凑测量结果。

你当前模块旋转了方向，读数也可能倒置。应按真实数值核对，不凭文字朝向猜距离；拿不准时保存属性窗口或模块读数截图再排查。

固定50cm时反复得到相同距离是正常的。这一轮验证电源、触发、回波计时和换算；舵机转动后模型距离不会自动随原理图中障碍物的位置改变。后续扫描阶段还需要按角度变化的测试输入。

## 9 看懂输出文字

50cm设置下，预期输出类似：

```text
S,1,status=0,echo_us=2900,distance_mm=500
S,2,status=0,echo_us=2900,distance_mm=500
S,3,status=0,echo_us=2900,distance_mm=500
```

| 字段 | 含义 |
|---|---|
| S后面的数字 | 样本编号，每次测量增加1 |
| status | 本次测量状态，0表示有效 |
| echo_us | 回波高电平持续时间，单位微秒 |
| distance_mm | 换算距离，单位毫米；无效时显示NA |

单位换算：1厘米=10毫米，1毫秒=1000微秒。本模型采用约58微秒对应1厘米，因此2900÷58=50厘米，也就是500毫米。

状态0并且距离正确，才支持测距成功。NA表示本次没有有效距离，不能将它解释成0毫米或障碍物非常近。

## 10 完成四项验收

每项至少保留5行连续输出。距离或接线改变时优先停止仿真，修改后重新运行；重启后样本编号会从1开始。

| 编号 | 设置或操作 | 预期回波 | 预期距离与状态 |
|---|---|---:|---|
| A | 超声距离50cm | 约2900微秒 | status=0，约500mm |
| B | 超声距离100cm | 约5800微秒 | status=0，约1000mm |
| C | 超声距离300cm | 约17400微秒 | status=0，约3000mm |
| D | 断开ECHO与PA0，把PA0接GND | 无上升沿 | status=1，echo_us=0，distance_mm=NA |

第一轮暂以回波宽度误差±10微秒作为排查阈值。这是工程检查阈值，不是实物传感器精度声明。如果所有距离都有固定倍数误差，应优先查时钟与计时频率。

### 10.1 无回波测试的接线顺序

1. 点击停止，确认仿真已停止。
2. 断开超声ECHO到PA0的连接。确保PA0与ECHO输出已分离，再把PA0接到GND。
3. 运行，预期终端持续输出status=1和NA；样本编号仍增加，程序不应卡死。
4. 再停止，去掉PA0接地线，恢复ECHO到PA0。
5. 恢复50cm，重新运行，确认有效测量能恢复。

这一项测试的是软件超时与恢复行为。它不等同于已经模拟了实际空间中的材质吸声、多径或所有传感器故障。

### 10.2 在记录里填写什么

将实际输出写入项目的测试记录，或保存对应截图。记录模板如下：

```text
测试编号 A
软件 Proteus 8.9
固件 SONAR_V01
输入设置 50cm
实际终端输出 复制至少5行
结论 通过或失败
截图路径 填写保存的位置
修改内容 填写本次改过的电源或属性
```

文档里的预期数值不能直接抄成实验结果。四项全部运行并留下记录后，才把第一阶段标为通过。

## 11 按现象排错

### 11.1 终端完全没有文字

依次检查：仿真是否运行、终端窗口是否打开、PA9是否接RXD、终端是否9600 8N1、F103是否加载`sonar_v01.hex`，然后检查3.3V隐藏供电、NRST高电平、BOOT0低电平。先找BOOT启动行。

如果CPU加载HEX失败，打开Simulation Errors窗口，看具体文件路径。相对路径失效时，重新选择本机固件的完整路径。不要把已有HEX复制到另一目录后仍保留错误路径。

### 11.2 有乱码

检查9600、8N1、Normal极性，以及F103固件和8MHz设置。不要一边改变波特率一边改变主控时钟，每次只改一项并重启观察。

### 11.3 有BOOT但测量状态不是0

| 状态 | 程序观察到什么 | 优先检查 |
|---:|---|---|
| 1 | 没有捕获到ECHO上升沿 | TR接PA1、ECHO接PA0、超声5V供电、触发脉冲 |
| 2 | 已捕获上升沿，但从TRIG结束起累计30ms内未等到下降沿 | 回波是否持续过长、模型距离与配置 |
| 3 | 触发前PA0已经是高电平 | ECHO误接电源、错误引脚、信号持续为高 |
| 4 | 捕获寄存器被后续边沿覆盖 | 额外脉冲、重复触发、多信号源误接 |
| 5 | 回波宽度不在174—29000微秒之间 | 距离设置、时钟与脉宽；本轮接受3—500cm |

状态1与状态3的原因不同：前者没等到回波，后者在触发前就已经为高，不能都靠增加延时解决。

### 11.4 距离始终为同一个值

没有改模型距离时，这是正常重复测量。若设为100cm仍输出500mm，确认你改的是距离设定值，停止后重新运行，再核对模块实际读数和程序文件。只有50cm一项通过还不够验证换算比例。

### 11.5 LED看起来不亮或GPIO是灰色

本工程此前出现过模拟LED模型影响PB0显示的情况；已通过的LED副本使用Digital设置。保留该设置，先以终端数据判断测距。PB0只是每个测量循环翻转一次的心跳，并非固定频率标定灯。

灰色GPIO只表示当前逻辑显示不能确认状态，不能直接推出程序没运行。先看BOOT和样本编号，再测波形。

## 12 必要时使用示波器

若有BOOT但始终测不到距离，增加OSCILLOSCOPE，A通道接PA1/TR，B通道接PA0/ECHO。共享原理图地作为参考。

预期TR为约15微秒高脉冲；超声模型要求至少10微秒。50cm时ECHO高电平约2.9毫秒。用毫秒时基看ECHO，例如从1毫秒每格开始；看TR时再改到微秒级时基，例如5或10微秒每格。

不能在一个较慢时基下看不到窄TR脉冲，就断言没有触发。若ECHO的宽度正确而串口换算错误，检查F103捕获计时；若TR正常且超声VCC有效，但ECHO仍无变化，检查传感器模型和接线。

保存TR与ECHO的波形，以及对应终端输出。波形与文字相互对应，比单张LED截图更有排错价值。

阶段通过标准是输入、处理、输出都能观察到。先单独跑通，再集成；不要同时增加舵机、屏幕、按键和上位机后一起排错。

## 15 仿真与实物的区别

本轮HCSR04数字模型ECHO直接接PA0，用于验证仿真计时。实物模块常用5V供电，PA0不是5V容忍引脚，搭实物时要做电平适配；不能直接复制这条仿真连接。

普通舵机有有限行程，整圈扫描需要另选旋转机构并处理定位。HCSR04默认距离不会随舵机角度自动变化。本手册的验证范围仅限固定距离输入与主控计时，本轮实际运行验收尚未完成。

仿真时间可能比现实时间慢。串口输出更新速度、界面动画帧率与实际测量周期是不同指标，后续记录结果时应分别说明。
