# 回波超时诊断

日期：2026年10月14日。用户加载V01_1后，终端持续输出status=1、echo_us=0、distance_mm=NA，样本编号增加。GPIO诊断也持续status=1，tim2_sr=0/1。重启Proteus后用户反馈不再出现内部异常，最新截图包含正确诊断BOOT行和S,1—17。尚未观察到PA0回波，下一步检查模块端波形。

## 先做一项对照

停止仿真，将U1的Program File换为以下文件，保留现有接线和超声模型50cm输入，再运行：

```text
D:\仿真创新大赛\sonar_edu\firmware\build\sonar_echo_diag.hex
```

诊断启动行是BOOT,SONAR_DIAG_GPIO,HSI=8000000,BAUD=9600。该程序使用相同的8MHz时钟、15微秒触发及电源/接线假设；仅将回波边沿观察改为直接轮询PA0电平，并输出TIM2状态寄存器tim2_sr。现已观察到诊断固件运行，但测距未通过。

- status=0且distance_mm约500：GPIO读到了完整回波，继续检查TIM2捕获路径。轮询有采样延迟，这个距离不能代替精度验收。
- status=1：GPIO也没读到上升沿。下一步用示波器A接模块TR、B接模块ECHO，检查15微秒触发与约2.9毫秒回波，并核对模块VCC实际5V及共同地。
- status=2：GPIO已读到高电平，但从TR结束起累计30毫秒内没观察到下降沿。
- status=3：触发之前PA0已高，先查误接电源或信号持续高。
- status=5：确实测到了脉冲，但宽度超出本轮3—500cm范围。

示波器接在模块引脚处与接在主控引脚处，可进一步区分模型是否产生回波和导线是否连接到PA0。窄TR脉冲需要微秒级时基，ECHO则用毫秒级时基。不要用GPIO静态颜色判断整个脉冲过程。

## 示波器操作

1. 停止仿真，在左侧虚拟仪器模式选择OSCILLOSCOPE并放置。
2. A从超声模块TR引脚处接一条支线，B从模块ECHO处接一条支线。保留原来的PA1和PA0连接。
3. 运行后显示示波器窗口；未弹出时从调试菜单显示它。
4. A和B均选DC、2V每格，启用两通道；Horizontal时基先1ms每格。Trigger选A、上升沿，电平约1V，打开Auto，先关闭One-Shot。
5. 50cm下B预期有约2.9ms高电平。A的15us脉冲在这个时基下会很窄；不能凭它难以看清认定没有TR。
6. 再把时基改10us每格，检查A脉宽是否至少10us。发图时保留右侧全部控制面板，便于确认时基、通道是否开启及触发设置。

两张图都没有脉冲时仍需排除仪器设置；A达到触发条件而B持续低，下一步测模块VCC实际电压及模型诊断信息；B有回波而GPIO未收到，检查ECHO与PA0是否同一网络。

仪器控制参考：[Labcenter官方示波器操作说明](https://www.labcenter.com/blog/sim-scope-controls/)。

诊断程序只用于定位，不修改原V01_1测距算法；源文件src/echo_diagnostic.c及条件分支位于firmware/src。构建脚本firmware/build-echo-diagnostic.ps1已通过ARMCC5编译、HEX校验与去除semihosting断点检查。
