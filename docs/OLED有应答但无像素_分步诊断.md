# OLED有应答但无像素：分步诊断

> 2026-10-16更新：以下是旧V02实验说明，不再作为当前复现入口。旧ACK判定会误报成功，V02被2A负对照挡在INIT，未进入全亮。修正后V05在原3.3V接线上探测到3D并实测显示棋盘格和完整文字。请优先看[最新通过工程与原因](OLED黑屏定位与已通过工程_2026-10-16.md)。

日期：2026年10月15日。用户确认此前看到的“亮”只是蓝色背景，不是文字或像素。最新运行截图为黑色显示区域，仍无文字。底色变化不能单独证明显示通过。

## 已观察到的进展

- 上拉已从串联改为分支；最近备份中R3/R4下方的未标名POWER端子绑定默认VCC=3.3V。箭头朝下不意味着接地，不能只看箭头方向判断。
- 终端显示`OLED,ACK=1,ADDR=3C`。
- 两行输出为cmd/pa1分别0/0及1/1，pa0=0，`screen_write=1,bus_error=0`。
- 用户反馈PB0的LED随命令亮灭，SCL/SDA信号有活动。

当时可确认单片机运行和GPIO读回；I2C“应答成功”后来被负对照及原始采样否定，不能记作有效通信证据。OLED已在后续V05通过文字显示，超声距离尚未验收。

## 为什么串口看起来慢

V01在每次报告前保持输出750ms，并用软件I2C发送整帧1024字节；还有GPIO、计时器轮询与串口发送开销。Proteus可能比真实时间慢，不能用墙上经过的秒数直接推断串口坏了。优先看仿真时间是否推进以及BOOT、后续样本是否持续出现。

V02改为分阶段，日志出现的间隔也不同于V01；每阶段保持约1秒仿真时间，写帧另计。没有新增串口输入或测距计算。

## 新测试只换HEX，先保持现有接线

停止仿真，编辑U1的Program File，改为：

```text
D:\仿真创新大赛\sonar_edu\firmware\build\oled_panel_diag_v02.hex
```

串口仍9600 8N1、PA9→RXD，PA1保持隔离。重新开始后，BOOT必须为：

```text
BOOT,OLED_PANEL_V02,HSI=8000000,BAUD=9600
INFO,PER_COMMAND_TX,PIXEL_PACKET=16,HOLD_MS=1000
```

本机配套Arduino示例每次I2C事务发送一个命令字节、每包16个像素字节；V02采用相同分包粒度作兼容性对照。原V01连续命令传输按SSD1306协议是允许的，不能仅凭改变分包方式就宣布找到根因。

初始化后还探测本测试中没有器件的2A地址，正常应出现`NEGATIVE,ADDR=2A,ACK=0,EXPECTED`。若反而ACK=1，应先检查ACK采样或网络，不能直接信任所有“成功”输出。

然后循环四个阶段：

| 串口stage | 预期画面 | 用来区分什么 |
|---|---|---|
| ALL_ON | 整个有效显示区域出现明显亮像素 | A5命令绕过RAM，先检验显示使能/显示模型 |
| OFF | 有效显示像素关闭 | AE关闭命令是否影响画面 |
| CHECKER | 交替像素的棋盘格 | RAM写入、地址窗口与数据通道 |
| TEXT | OLED READY、GPIO TEST、CMD/PA1/ECHO文字 | 字模与帧缓冲文字显示 |

日志例子是预期格式，不是本机已经测到的结果：

```text
P,stage=ALL_ON,write_ack=1,bus_error=0,reset=1,scl=1,sda=1
P,stage=OFF,write_ack=1,bus_error=0,reset=1,scl=1,sda=1
P,stage=CHECKER,write_ack=1,bus_error=0,reset=1,scl=1,sda=1
P,stage=TEXT,write_ack=1,bus_error=0,reset=1,scl=1,sda=1
```

reset/scl/sda为命令结束、总线释放后的GPIO读回。write_ack仍只表示事务应答，画面要同时观察。V02的PA1保持低电平，PB0表示测试阶段，不再承诺像V01那样逐条cmd交替。

## 按结果继续

- 全亮和关闭均有明显变化、文字也出现：记录V02固件和画面，进一步比较原事务与分包差异；不能倒推原硬件已完全无问题。
- 全亮/关闭响应，但棋盘格和文字没有：重点查RAM数据及地址窗口。
- 棋盘格有、文字没有：重点查字模与文字帧缓冲。
- 所有阶段write_ack=1但都没有像素：下一步对照本机原厂工程、显示模型属性与电源/复位状态；先不继续调超声或舵机。
- INIT或某阶段应答失败：按日志错误码、reset和总线空闲电平检查电气连接。

V02实际运行只反复INIT并报2A意外应答；后续V05修正ACK后已出图。不要继续使用旧V02判断修复结果。

协议依据：[SSD1306手册8.1.5及10.1.9/10.1.12节](https://cdn-shop.adafruit.com/datasheets/SSD1306.pdf)。A5强制全亮、A4恢复RAM显示、AE关闭、AF开启。实际裸屏的VDD与VCC应遵守[屏幕规格书](https://www.adafruit.com/datasheets/UG-2864HSWEG01.pdf)，当前仿真片段仍不能作为完整实物供电设计。
