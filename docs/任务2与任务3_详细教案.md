# 任务 2：方向与扫描（8 分钟）

## 要让学生理解的一件事

> **只测距离，只能知道"有多远"；加上转动，才能知道"在哪边"。**

## 关键前提（老师必须先知道）

| 数据来源 | 看到什么 | 能讲什么 |
|---|---|---|
| **串口（真实器件）** | 所有点的半径**一样**，形成一段圆弧 | 只能讲"角度 = 方向"这个对应关系 |
| **内置模拟（网页几何场景）** | 不同方向的距离**不同**，有方块和圆柱 | 才能讲"方向 + 距离才能描述障碍" |

原因：仿真里的超声模型距离是**固定设定值**，不随角度变化。所以：

- **方向感**要靠"角度"讲（真实数据也能讲）
- **空间关系**要靠"内置模拟"讲（网页按几何场景计算交点）

两者都要用，并且要**明确告诉学生这是两种数据**，不要混为一谈。

## 时间分配

| 时间 | 环节 |
|---|---|
| 0:00-2:00 | 用串口数据建立"角度 = 方向" |
| 2:00-5:00 | 切换到内置模拟，看不同方向的距离差异 |
| 5:00-8:00 | 回到串口，提问与小结 |

## 详细流程

### 环节 1（0:00-2:00）角度就是方向

**老师操作**

1. 保持串口连接，扫描运行中
2. 指着网页右侧扇形图上的刻度：`0°` 在右、`90°` 在上、`180°` 在左
3. 让学生盯着屏幕，数一数：探头转一格，点移动多少

**学生任务**：在记录单上填三行，角度分别取 30°、90°、150°，并写明"在左边/前方/右边"。

**屏幕预期**

```
终端：SCAN,12,90,1400,OK,PROTEUS
网页：探头角度 90°   当前测距 140.0 cm
```

**提问**

- 探头现在指着哪一边？（看角度数）
- 屏幕上的点出现在哪个方向？（看扇形图）
- 角度变大，点在往哪边移动？

**要落到的结论**：**角度就是方向**。探头转到哪个角度，这一次测量说的就是那个方向的事。

### 环节 2（2:00-5:00）为什么需要方向 + 距离

**老师操作**

1. 网页右上角「连接与数据」→ 数据来源改成 **「内置模拟」**
2. 选一个场景（如"方块与圆柱"）
3. 让扫描跑一圈

**学生任务**：观察不同角度上的点，**距离是否一样**；找出最近的方向，在记录单上写"最近的障碍在 ___ 度方向，距离约 ___ cm"。

**屏幕预期**

- 点迹不再是一段等半径圆弧，而是**有的近、有的远**
- 3D 视图里能看到方块和圆柱的位置

**提问（分两层）**

| 层次 | 问题 |
|---|---|
| 基础 | 所有方向的距离都一样吗？ |
| 进阶 | 如果只能告诉你"前面 60cm 有东西"，你能找到它吗？ |
| 挑战 | 现在告诉你"60° 方向、40cm"，你能指出它在哪吗？ |

**要落到的结论**：**一个障碍需要两个数才能说清 —— 方向 + 距离。**

### 环节 3（5:00-8:00）回到真实数据

**老师操作**

1. 数据来源切回 **「浏览器串口」**，重新连接 COM33
2. 扫描继续

**要跟学生说清楚的一段话（原话可用）**

> 刚才那个有方块、有圆柱的画面，是电脑**算**出来的，用来帮我们看清空间关系。
> 现在这个画面，是**真的传感器**测出来的。你会注意到它的点都在同一个圈上 —— 不是因为它看不见，而是因为这次实验里，我们把目标距离**固定设成了 140 厘米**。
> 真实的雷达前面如果真有东西挡着，不同方向的读数就会不一样。

**提问**

- 两种画面，一种是算出来的，一种是测出来的，怎么分辨？（看来源标签：SIM / PROTEUS）
- 为什么真实的这一次所有方向都一样远？（因为目标距离是设定的）

## 常见误区与纠正

| 学生说 | 纠正 |
|---|---|
| "雷达看到了一个圆形的墙" | 不是。所有点等距是因为目标距离被设定成固定值，不是真有圆形障碍 |
| "左边没有东西" | 只能说"左边这个方向这一次没有测到更近的物体" |
| "它知道那是什么东西" | 不知道。它只知道"那个方向、那个距离有东西弹回了声音" |

## 记录单怎么填

| # | 我的预测（哪个方向最近） | 角度 | 距离 | 状态 | 和预测一样吗 |
|---|---|---|---|---|---|
| 1 | | 30° | | | |
| 2 | | 90° | | | |
| 3 | | 150° | | | |

# 任务 3：测不到怎么办（6 分钟）

## 要让学生理解的一件事

> **没有读数，不等于前方安全。不知道 ≠ 安全。**

## 三种"没数据"，含义完全不同

| 现象 | 屏幕上显示 | 真实含义 | 怎么造出来 |
|---|---|---|---|
| **超量程** | 无可靠量程内测量 | 目标比 250cm 还远，测不到 | 把模块距离改到 **260cm** |
| **回波超时** | 无可靠量程内测量 | 目标太近、太软、角度太斜，回声太弱 | 把模块距离改到 **低于下限**（如 2cm） |
| **数据中断** | 数据已超时 | **系统本身出问题**（仿真停了、线断了） | **暂停仿真** 2 秒 |

> 前两种是"传感器的极限"，第三种是"系统故障"。**三种都不是"安全"。**

## 时间分配

| 时间 | 环节 |
|---|---|
| 0:00-2:00 | 制造超量程 |
| 2:00-4:00 | 制造回波超时 |
| 4:00-6:00 | 制造数据中断 + 小结 |

## 详细流程

### 环节 1（0:00-2:00）超量程

**老师操作**：点超声模块的向上箭头，把距离从 140 → **260 cm**

**屏幕预期**

```
终端：SCAN,20,120,NA,NO_HIT,PROTEUS
网页：探测状态 → 无可靠量程内测量
```

**提问**

- 现在屏幕上没有读数了，前面是空的吗？
- 如果我们把距离改回 140，读数会不会回来？

**要落到的结论**：**没测到，只是"超出我的能力范围"，不是"那里什么都没有"。**

### 环节 2（2:00-4:00）回波超时

**老师操作**：把距离改到 **2 cm**（低于模型下限 3cm）

**屏幕预期**

```
终端：SCAN,30,150,NA,TIMEOUT,PROTEUS
网页：探测状态 → 无可靠量程内测量
```

**提问**

- 这次也是"没读数"，和上一次的原因一样吗？
- 一枚很软的布、一块斜着的板子，会不会也这样？

**要落到的结论**：**物体太近、太软、太斜，回波会太弱 —— 探测不到不等于不存在。**

### 环节 3（4:00-6:00）数据中断 + 小结

**老师操作**：点 Proteus 的**暂停**

**屏幕预期**

```
2 秒后：网页右上角 → 数据已超时
        探测状态 → 无可靠量程内测量
```

**提问（这是最重要的一问）**

> 刚才三种"没读数"：
> ① 太远了 ② 太近/太软 ③ 电脑和板子断了
>
> 哪一种是"可以放心往前走"？

**要落到的结论**：**都不是。** 没读数只能说明"我不知道"，不能说明"没有危险"。**这一条是安全判断的底线。**

## 老师可以补充的一句

> 真正的自动驾驶或机器人，遇到"测不到"时会**减速、停车、或者报警让人接手**，绝不会当作"前方畅通"。

## 常见误区与纠正

| 学生说 | 纠正 |
|---|---|
| "没显示就是没有东西" | 不对，可能是太远、太近、太软，或者系统断了 |
| "系统坏了才叫出问题" | 传感器测不到也是问题，只是不报错 |
| "改回距离就有读数了，说明原来没事" | 那是因为我们**人为**把目标放回来了；现实中你不知道障碍还在不在 |

## 记录单怎么填

| # | 我做了什么 | 屏幕显示 | 我觉得是什么意思 |
|---|---|---|---|
| 1 | 距离改成 260cm | 无可靠量程内测量 | |
| 2 | 距离改成 2cm | 无可靠量程内测量 | |
| 3 | 暂停仿真 | 数据已超时 | |

---

## 附：两个任务的失败预案

| 问题 | 处理 |
|---|---|
| 改距离后网页不更新 | 确认网页数据来源是「浏览器串口」且已连接；仿真在运行 |
| 制造不出超时 | 先把距离改到 260cm，等 2~3 秒；若仍 OK，说明量程上限判断未触发，可改用"暂停仿真"演示数据中断 |
| 内置模拟看不到方块 | 换一个预设场景；或直接讲"不同方向距离不同"这一现象 |
| 学生问"为什么真实数据是个圆" | 按环节 3 的原话解释：目标距离是设定的，不是真的有一圈墙 |
